How the engine works

Formal model. An NFA is a 5-tuple N = (Q, Σ, δ, q₀, F) where δ : Q × (Σ ∪ {ε}) → P(Q) returns a set of next states. A string w is accepted iff some sequence of choices consumes all of w and ends in a state of F.

Parallel-path simulation (the subset idea). Keep the set S of every state the machine could be in. Start with S = ECLOSE({q₀}). For each symbol a: S ← ECLOSE( ∪s∈S δ(s, a) ). Accept iff S ∩ F ≠ ∅. Time O(n · (|Q| + |δ|)) for a string of length n; space O(|Q|). If S ever becomes empty, every thread has died and the string is rejected.

Backtracking simulation. Depth-first search over configurations (state, position). Take one option, go as deep as possible, and when stuck undo the last choice and try the next one. Stop at the first accepting path. Two guards keep it finite: an ε-cycle check (a configuration already on the current path is skipped) and a memo of configurations already proven to fail. Without the memo, backtracking can take exponential time — try the third symbol from the end is 1 preset on a long string.

Both methods always agree on the answer; the app runs both and tells you if they ever differ.
